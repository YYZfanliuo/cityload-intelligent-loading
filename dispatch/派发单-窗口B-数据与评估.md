## 你的任务清单

### T02 · 数据 schema + 30 门店数据生成器【截止 10/11 13:00 —— 最高优先级】

**输入**：`docs/interfaces.md` 第 1 章（输入数据结构）
**交付物**：
1. `data/schema.md` —— 字段说明文档（可复用接口契约第 1 章内容 + 补充取值分布说明）
2. `data/gen_data.py` —— 可参数化数据生成器，命令行用法：
   ```bash
   python data/gen_data.py --stores 30 --seed 42 --out data/
   ```
3. 生成好的数据集（4 个文件）：
   ```
   data/orders.json      # 30 门店，每店 5–15 个 SKU 行，总约 300 SKU 行
   data/vehicles.json    # 至少 2 种车型（4.2米厢式货车 ×4、依维柯 ×3）
   data/network.json     # 含距离矩阵与时长矩阵
   data/rules.json       # 装载与调度规则
   ```

**业务背景（必须贴合赛题）**：连锁药店配送 —— 中心仓（杭州萧山）每天向 30 家门店配送药品，SKU 含不同规格的OTC药品、保健品、日用品。

**生成规则要求**：
| 项 | 要求 |
|----|------|
| 门店位置 | 以中心仓 (30.2741, 120.1551) 为中心，半径 3–25 km 随机分布 |
| 时间窗 | 随机分配 `08:00–12:00`、`12:00–16:00`、`14:00–18:00` 三类 |
| SKU 尺寸 | 单件长宽高 5–40 cm 随机，重量 0.05–3.0 kg 随机 |
| 易碎品 | 约 8% 的 SKU 标记 `fragile: true` |
| 堆叠 | 约 15% 标记 `stackable: false`，其余 `max_stack_layers` 取 3–8 |
| 距离矩阵 | 用经纬度做 Haversine 计算；时长 = 距离 / 30 km/h × 60 |
| 可复现 | 同一 `--seed` 必须产出完全相同的数据 |

**验收标准**：
- 生成的 4 个文件完全符合 `docs/interfaces.md` 第 1 章结构
- 换 seed 重跑数据不同，同 seed 重跑数据完全一致
- 总订单量使得 2–4 辆车能装下，且存在一定装载优化空间（不要太松也不要装不下，建议总重量占所有车额定载重的 55%–75%）

### T15 · 评估指标模块【截止 10/11 18:00】

**输入**：`docs/interfaces.md` 第 2.5 与 3.1/3.2/3.4 节
**交付物**：`eval/metrics.py`（实现 `compute_metrics`）+ `tests/test_metrics.py`

**必须计算的指标**：
| 指标 | 定义 |
|------|------|
| `vehicle_count` | 使用车辆总数 |
| `total_distance_km` | 总行驶里程 |
| `total_cost` | 总成本 = Σ(固定成本 + 里程 × 每公里成本) |
| `avg_weight_load_rate` | 平均载重利用率 = 实际载重 / 最大载重 |
| `avg_volume_utilization` | 平均体积利用率 = 已放货物体积 / 车厢容积 |
| `on_time_rate` | 时效达成率 = 按时抵达门店数 / 总门店数 |
| `unassigned_order_count` | 未分配订单数 |
| `solve_time_sec` | 求解耗时（由调用方传入或读取） |
| `peak_memory_mb` | 峰值内存（用 `tracemalloc` 或 `psutil`） |

**验收标准**：
- 输入任意合法的 routes/packing 结果，输出统一 `metrics.json` 结构
- 用手算样例验证成本、载重率、体积率公式正确（至少 2 个手算 case 写在单测里）
- 单测 `pytest tests/test_metrics.py` 全绿

### T33 · 测试记录与边界 case 清单【截止 10/12 12:00】

**输入**：全部算法与数据代码
**交付物**：`docs/testing.md`，包含：
1. 单测清单与运行结果（`pytest -v` 输出摘要）
2. 边界 case 清单，至少覆盖：
   - 订单超载（单订单重量 > 单车载重）
   - 时间窗无法满足（距离过远 + 时间窗过窄）
   - 易碎品堆叠冲突
   - 空订单 / 单门店场景
   - 车辆数不足导致订单未分配
3. 每类边界 case 的**实际表现**（是否优雅处理、是否报错）

**验收标准**：所列 case 均实测过，有真实输出记录，非推测。
