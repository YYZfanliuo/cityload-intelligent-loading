# 派发单 · 窗口E（T50d：一句话下单 → 智能配载 端到端串联）

> **背景**：用户指出当前断点——"自然语言解析"与"智能配载"是两个分离的演示区。
> 本任务把两者串联成端到端流程：**输入一句话 → 解析 → 一键并入场景 → 重跑配载 → 展示新方案**。
> **时间盒**：1.5 小时（10:20–12:00），超时降级或放弃，不阻塞主线。

---

## 功能规格（MVP）

### 触发入口
- 自然语言解析**成功**后，在解析结果下方展示按钮：
  - 中文模式：「将此订单加入场景并运行智能配载」
  - 英文模式：Run Loading Optimization with This Order
- 解析失败 / 无货物明细时：按钮禁用并给出提示。

### 执行链路（点击按钮后）
1. **字段补全**（app 层实现，不编造数据）：
   - 门店匹配：用解析出的门店名/编号，在**当前数据集的门店库**（data/orders.json 的门店列表）中反查 → 补 `store_id`、`lat`、`lng`、标准门店名；
   - `order_id` 自动生成（如 `OMERGE-001`，不与该场景已有 ID 冲突）；
   - SKU 物理参数：沿用解析器已做的 SKU 库匹配结果；
   - **匹配失败处理**：若门店不在门店铺（即不在当前配送网络内）→ 明确提示
     「该门店不在当前配送网络内，暂无法加入场景」（诚实边界，不编造坐标）。
2. **订单并入**：把补全后的新订单追加到订单列表，写为**临时数据集**：
   - 临时目录：`outputs/app-tmp/merged-scene/`（复制 vehicles/network/rules，生成合并后的 orders.json）；
   - 交付物必须隔离在此目录，**不得**改动 data/ 与 outputs/t25-final 等已入库产物。
3. **重跑配载**：对临时数据集调用既有管线（复用 run.py 的求解链路；不改动任何核心模块）；
4. **结果展示**（页面内）：
   - 新方案核心指标：车辆数 / 总里程 / 运输费 / 装下率（与基线对比可略）；
   - **重点**：该新订单被分配到哪辆车（车次）、在路线中的送达次序；
   - 展示新的路线图（route_map.png，临时目录内生成）；如时间允许展示该车次 3D 图。

### 边界与错误处理
- 无门店匹配 / 解析错误 / 管线异常：页面明确提示，不白屏、不抛异常；
- 无 Key 时该功能**照常可用**（解析走规则引擎——可能解析质量较低，但链路完整）；
- 会话内重复点击可重复执行（覆盖临时目录）。

## 硬约束（沿用 T50 系列）

1. 只允许修改 `app.py` 与 `tests/test_app_t50.py`；solver/eval/agent/report/run.py 零改动；
2. 产物全部隔离在 `outputs/app-tmp/` 下；
3. 回归：`CITYLOAD_APP_TEST=1 pytest tests/test_app_t50.py` 全绿（新增用例：合并链路 happy path + 门店不匹配 + 解析失败禁用按钮）；
4. 中英文双语（新增 UI 文案）；
5. 完成后推送 dev + 按格式回报。

## 验收标准

- 输入解析成功的订单 → 点按钮 → 页面出结果：该订单的车次分配 + 新方案指标 + 路线图；
- 输入不在库的门店 → 明确提示，不崩溃；
- 无 Key 全链路可用；有 Key 时解析质量更高（一句话完整链路可演示）；
- 已入库产物零改动（git diff 验证）。
