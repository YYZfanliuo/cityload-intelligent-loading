## 2. 字段结构（速查，完整约束见 `docs/interfaces.md` §1）

### 2.1 `orders.json`

```
meta:      {scenario, date, seed, warehouse{id,name,lat,lng}}
orders[]:  {order_id, store_id, store_name, lat, lng, time_window[2], service_minutes,
            items[]: {sku, name, qty, weight_kg, length_cm, width_cm, height_cm,
                      fragile, stackable, max_stack_layers}}
```

### 2.2 `vehicles.json`

```
vehicles[]: {vehicle_id, type, max_weight_kg, cargo_length_cm, cargo_width_cm,
             cargo_height_cm, count, cost_per_km, fixed_cost, avg_speed_kmh, max_work_minutes}
```

### 2.3 `network.json`

```
nodes[]:                {id, lat, lng}                # 顺序：WH01, S01...S30
distance_matrix_km:     N×N 对称方阵（Haversine，单位 km）
duration_matrix_min:    N×N 对称方阵（= 距离 / 30 km/h × 60，单位分钟）
node_order:             ["WH01","S01",...]            # 定义矩阵行列顺序
```

### 2.4 `rules.json`

装载：`allow_rotation=true`、旋转轴 `["lwh","wlh","hlw"]`、考虑易碎与最大堆叠层数、间隙 0；
调度：尊重时间窗、超时罚 2.0 元/分钟、未分配罚 1000 元/单。

## 3. 取值分布与生成规则

| 项 | 规则 | 说明 |
|----|------|------|
| 门店位置 | 以中心仓为圆心、半径 U(3, 25) km 随机方位分布 | 生成后用 Haversine 校验，超界重采样 |
| 门店数 | `--stores`（默认 30），编号 S01…S30 | 订单号 O0001…O0030 |
| 时间窗 | 等概率抽取：`08:00–12:00` / `12:00–16:00` / `14:00–18:00` | 三类，结束 > 开始 |
| 卸货服务时长 | randint(10, 25) 分钟/店 | service_minutes |
| SKU 目录 | 150 个全局 SKU = 20 个 OTC 品名 ×3 规格 + 15 个保健品 ×3 + 15 个日用品 ×3 | 同一 SKU 编码在各店规格一致 |
| 每店 SKU 行数 | randint(5, 15)，同店不重复选品，30 店合计 ≈ 300 行 | 实测均值 ≈ 300 |
| 单行数量 qty | randint(3, 22)（生成后经总重校准微调，clamp 到 ≥1） | |
| 单件重量 | U(0.05, 3.0) kg，round 2 位 | 全局统一，范围严守契约 |
| 单件尺寸 | 基础边长按品类分层：OTC U(6,18)、保健品 U(9,26)、日用品 U(12,32) cm，再乘比例系数 (l:1.0–1.3, w:0.7–1.1, h:0.5–0.9) | 全部 clamp+round 到 5–40 cm 契约范围内；品类分层是为贴近真实包装 |
| 易碎 fragile | 目录级配额校正至 **恰好 8%**（150 个中 12 个） | 行级实际占比 ≈ 7%–9% |
| 不可堆叠 stackable=false | 目录级配额校正至 **≈15%**（150 个中 23 个） | 行级实际占比 ≈ 13%–19% |
| 最大堆叠层数 | stackable=true → randint(3, 8)；false → 1 | |
| 距离矩阵 | Haversine（R=6371.0088 km），round 4 位，严格对称 | 门店与矩阵坐标同源，保证一致 |
| 时长矩阵 | 距离 / 30 km/h × 60，round 2 位 | 与车辆 avg_speed_kmh=30 一致 |

### 车辆参数

| vehicle_id | 车型 | 载重 | 车厢 (长×宽×高 cm) | 数量 | 每公里 | 固定 | 速度 | 最长工时 |
|------------|------|------|--------------------|------|--------|------|------|----------|
| V01 | 4.2米厢式货车 | 1700 kg | 420×200×200 | 4 | ¥3.5 | ¥120 | 30 km/h | 480 min |
| V02 | 依维柯 | 1000 kg | 340×180×180 | 3 | ¥2.8 | ¥80 | 30 km/h | 480 min |

运力池额定总载重 = 4×1700 + 3×1000 = **9800 kg**。

## 4. 总重校准机制（关键设计）

验收标准要求「总重量占所有车额定载重的 55%–75%，且 2–4 辆车能装下」。
生成器在写盘前执行 **确定性的总量校准**：按比例缩放各行 `qty`（round 后 clamp ≥1），
把总货重收敛到 **5500–5850 kg（≈56%–60%）** 区间：

- 下限保护：不低于 5500 kg（> 55% 线 5390 kg），避免"太松"；
- 上限保护：不超过 5850 kg，保证 **4 辆 V01（6800 kg）可装下**且留 950+ kg 余量（"不要太紧"）；
- 校准只依赖同一 RNG 序列，**不破坏可复现性**。

## 5. 复现方法

```bash
# 默认：30 门店 / seed 42 / 输出 data/
python data/gen_data.py

# 完整参数
python data/gen_data.py --stores 30 --seed 42 --out data/

# 换一组数据（如实验用的第二组数据集）
python data/gen_data.py --stores 30 --seed 43 --out data_alt/
```

- **同 seed 重跑 → 4 个文件字节级完全一致**（已验证：`diff` 通过）；
- **换 seed → 数据不同**（已验证）；
- 写出统一使用 `\n` 换行、UTF-8、`indent=2`，保证跨平台一致性。
