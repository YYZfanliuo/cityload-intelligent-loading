## 二、业务场景

复刻赛题给定的真实业务场景：**中心仓 → 30 家连锁药店的城市配送**。中心仓每天需要向多家门店配送数百个 SKU 的药品，同时满足：

- **车辆容量**：载重与车厢容积双重约束；
- **装载条件**：货物易碎性（不可承压）、不可堆叠限制、堆叠层数限制、车厢空间结构；
- **交付时效**：各门店有配送时间窗口（08:00–12:00 / 12:00–16:00 / 14:00–18:00）；
- **执行顺序**：装载顺序必须与门店交付顺序协同，减少卸货时的重复搬运（翻箱）。

当前行业中这些环节高度依赖人工经验，难以在多重约束下综合优化。本系统将**运力匹配与路线优化、3D 装载规划、装卸顺序指导**串成一条可运行的智能管线，并给出与人工经验式基线（贪心策略）的量化对比。

## 三、核心方案

**三个算法模块 + 一条自动化管线：**

1. **智能运力匹配与路线优化**（`solver/routing.py`）
   OR-Tools CVRPTW 建模：载重容量、时间窗、单车工时、多车型成本；目标为固定成本 + 里程成本 + 超时惩罚的综合最小化；无可行任务的订单进入未分配清单而非直接丢弃。OR-Tools 不可用时自动降级为确定性近邻构造（保证离线可运行）。

2. **智能装载规划**（`solver/packing.py`）
   自研 3D 层叠装箱启发式：不超重、不越界、箱体不重叠；易碎件"上方无物 + 下方完整支撑"、不可堆叠件上方禁放、逐堆垛层数限制；支持旋转配置；无法装入的货物进入 `unplaced` 如实上报（不放松安全约束）。

3. **智能装卸指导**（`solver/sequencing.py` + `agent/explainer.py`）
   按门店交付顺序生成**逆序装载方案**（后送达先装载）；自动检测"上下压 / 车尾通道"两类阻挡并如实告警；生成分步骤装卸指引文本（模板化生成，可选 LLM 润色，带多重校验兜底）。

**对比基线**（`solver/baseline.py`）：模拟人工经验策略——就近分组、按门店编号顺序访问、原顺序装填。

**LLM 智能层**（`agent/parser.py`）：自然语言订单需求解析（支持多轮问答式需求理解），解析失败自动回退结构化输入旁路，**LLM 不构成主流程必经环节**。

## 四、技术架构

```
data/（模拟数据：orders / vehicles / network / rules）
        │
        ▼
[solve_routing] ──→ routes.json          CVRPTW：OR-Tools 9.15
        │
        ▼
[solve_packing] ──→ packing.json         3D 装箱启发式
        │
        ▼
[sequence_loading] → loading_plan.json   交付顺序协同装载
        │
        ├──→ [compute_metrics]  → metrics.json（含对比节）
        ├──→ [render_figures]   → 路线图 + 3D 装载图 + 分步图
        └──→ [gen_guide_text]   → guide_text.json（装卸指引）
                    │
                    ▼
              [build_html] → report.html（单页可离线打开）
```

- **技术栈**：Python 3.10+（实测 3.13）、OR-Tools、NumPy / pandas、matplotlib、pytest
- **模块边界与接口契约**：`docs/interfaces.md`（唯一事实来源，数据流、函数签名、JSON 结构全部冻结）
- **一键入口**：`run.py`（一条命令跑完整管线并产出报告）

## 五、数据说明

**全部数据为模拟生成，不含任何真实业务数据。** 生成器 `data/gen_data.py` 参数化复刻赛题场景：

| 数据集 | 规模 | 内容 |
|--------|------|------|
| `data/`（seed=42） | 30 门店 / 328 SKU 行 / 3656 件 / 5720 kg | 订单+车辆+路网+规则四件套 |
| `data/seed7/`（seed=7） | 30 门店 / 318 SKU 行 / 3751 件 / 5721 kg | 第二组对照数据集 |

- **可复现**：固定 seed 下字节级可复现（已做 3 次 diff 验证）；字段说明见 `data/schema.md`
- **已知差异**：seed7 的易碎件占比（12.42%）高于 seed42（7.44%），装载难度更高（详细归因边界见 `experiments/results.md`）

## 七、实验结果

> 数字来源：`experiments/results.md`（T31b 锁定版，双轮 24 次实验、业务 SHA256 完全一致）。
> 实验环境：Python 3.13.14 / Windows 11 / OR-Tools 9.15.6755。

### 7.1 主口径：seed42（30 门店 / 3656 件）

| 指标 | 基准（贪心） | 优化方案 | 变化 |
|------|------------|----------|------|
| 车辆数 | 7 | **6** | -14.3% |
| 总里程 | 565.3 km | **287.1 km** | **-49.2%** |
| 固定成本 | ¥720 | ¥600 | |
| 里程成本 | ¥1,816.63 | ¥915.07 | |
| 超时惩罚 | ¥654 | **¥0** | 归零 |
| 运输费 | ¥3,190.63 | **¥1,515.07** | **-52.5%** |
| 未分配订单惩罚 | ¥2,000 | **¥0** | 归零 |
| 平均载重利用率 | 53.8% | **70.2%** | +16.4pp |
| 平均体积利用率 | 10.8% | **19.3%** | +8.5pp |
| 时效达成率 | 86.7% | **100%** | +13.3pp |
| 已装货物 | 2,759 / 3,656 件 | **3,591 / 3,656 件（98.2%）** | 未装 897 → 65 件 |

|------|------------|----------|------|
| 车辆数 | 7 | 5 | |

### 7.3 性能与可复现性（T32）

- **全链求解时间**（路线+装箱+排序）：优化方案 7.4–8.6 s，基线 0.5–0.7 s；进程峰值内存约 106 MiB —— 以时间换质量，30 店规模完全可接受（详见 `experiments/results.md` T32 节）。
- **可复现性**：冻结搜索配置（首解策略 + 自然下降 + 固定 ReSeed/SAT 随机种子、关闭 LNS）；双轮 24 次实验业务结果 SHA256 完全一致。可复现性限定同版本同环境（见 results.md 口径说明）。
- **诚实边界**：优化搜索为"自然下降完成"而非全局最优证明；跨 OR-Tools 版本不承诺严格一致。

## 八、应用价值

以 seed42 场景为例（单仓单日 30 店）：

- **直接成本**：单日运输费 ¥3,190.63 → ¥1,515.07，**节省 ¥1,675.56/日**；按 250 个工作日示意性估算，单仓年化节省约 **¥41.9 万**（估算示意，实际随业务量变化）。
- **运营质量**：时效达成率 86.7% → 100%（迟到费归零）；未分配订单 2 → 0；装载率提升减少空驶与趟次。
- **可解释与可执行**：3D 装载图 + 分步骤装卸指引可直接用于现场作业；阻挡检测主动告警，不掩盖问题。
- **工程可迁移**：模块化设计（接口契约冻结），可替换数据源接入企业实际订单/路网系统；算法配置可调（时间-质量权衡）。

## 九、当前限制与后续规划

**如实说明的已知限制：**

1. **装箱装下率**：seed42 全链 98.2%（未装 65 件），seed7 87.0%（未装 488 件）——剩余未装主要为易碎件与受限堆叠货物；系统以"不放松安全约束、如实上报"为原则。
2. **装卸阻挡**：排序模块检测到真实阻挡告警（如 seed42 各车 16–45 条），不承诺"无翻箱卸货"；告警已在报告中逐条披露。
3. **规模**：仅实测 30 店规模；100+ 店未实测，不给出运行时/内存承诺。扩展思路：地理与时间窗分区、初始解预热、子问题并行（详见 results.md T32 节）。
4. **动态场景**：未覆盖实时插单/重调度、多波次配送。
5. **LLM 环节为可选增强**（默认旁路），不影响主流程稳定性。

**后续规划**：易碎件专项装箱（提升 seed7 类场景）、拒装件业务代价纳入路由目标、动态重调度、真实数据接入试点。
